# Health4Ever OS — Digital Twin & Predictive Telemetry Simulator

Health4Ever OS is an open-source **Digital Twin & Predictive Telemetry Simulator** for Autonomous Biometric Apparel (ABA), leveraging **live environmental telemetry combined with deterministic NASA-STD-3001 physiological modeling**.

---

## Digital Twin & Hardware Boundary (Important Engineering Disclosure)

To maintain strict scientific and engineering transparency for reviewers and judges:

1. **What is Live & Public**:
   - **Environmental Inputs**: Real-time and forecast ambient temperature, apparent temperature, relative humidity, wind speed, and UV index from **Open-Meteo**; air quality (`US AQI`, `PM2.5`, `O₃`) from **Open-Meteo Air Quality**; and 10-day surface climatology & solar irradiance from **NASA POWER**.
   - **Spaceflight & Literature Feeds**: Real-time ISS orbital telemetry from **WhereTheISS**, space biology datasets from the **NASA Open Science Data Repository (OSDR)**, and peer-reviewed records from **NCBI PubMed** and **Crossref**.
2. **What is Modeled (Digital Twin Simulation)**:
   - Because physical carbon-nanotube / TENG bio-yarn garment hardware is currently in the textile blueprint & prototype stage, **the garment biometric outputs** (Modeled Core Temperature `°C`, Body Heat Storage `kJ/kg`, and Required Hydration Replenishment `mL/hr`) are **NOT streamed from physical on-body sensors**.
   - Instead, they are **deterministic analytical projections** generated by running published **NASA-STD-3001 Vol. 2** metabolic, thermal-storage, and fluid-intake equations against the live environmental telemetry, user-selected metabolic output (`147–617 W`), and garment thermal resistance (`clo`).

## Documented Standards & Physiological Equations

All thresholds in the simulator derive from published standards:

- **NASA-STD-3001 Vol. 2** (*NASA Space Flight Human-System Standard*):
  - **Body Heat Storage Operational Bounds**: `-1.9 kJ/kg < ΔQ_stored < +3.0 kJ/kg`
  - **Core Temperature Impairment Threshold**: `+0.6 °C` above resting `37.0 °C` baseline (`37.6 °C`)
  - **Skin Temperature Rise Threshold**: `+1.4 °C`
  - **Sustained Heart Rate Impairment Threshold**: `140 bpm`
  - **Minimum Potable Water Intake**: `240 mL/hr` (`8 fl oz/hr`)
  - **Nominal Metabolic Range**: `147 W – 617 W` (`528 – 2220 kJ/hr`)
- **International Space Agency Programs Referenced**:
  - **NASA**: OSDR (`osdr.nasa.gov`) & Human Research Program (HRP)
  - **ESA**: DLR `:envihab` bed-rest studies & Concordia Station polar analog research
  - **JAXA**: ISS *Kibo* biomedical & musculoskeletal adaptation studies
  - **CSA**: ISS *Bio-Monitor* wearable smart-shirt telemetry program

## Architecture

- **Frontend**: React 19, TypeScript, Vite, Tailwind CSS v4 (`src/`)
- **Backend Proxy (`server.ts`)**: Express server serving the Vite dev middleware (or `dist/` in production) and proxying CORS-restricted open-science APIs under `/api/*` with in-memory caching, last-known-good stale fallback, and per-source status reporting:
  - `GET /api/environment?lat=<lat>&lon=<lon>` — Aggregates Open-Meteo Forecast, Open-Meteo Air Quality, and NASA POWER.
  - `GET /api/space-sources?q=<query>` — Aggregates NASA OSDR, WhereTheISS, NCBI PubMed E-Utilities, and Crossref Works.

## Quick Start (Local Judge & Developer Testing)

### Prerequisites
- **Node.js `>= 20`** (tested on Node `v22.23.2`)
- **npm**
- No third-party API keys are required for any of the seven live public feeds.

### 1. Install Dependencies
```bash
npm install
```

### 2. Run in Development (Express Backend + Vite React Frontend on Port 3000)
```bash
npm run dev
```
Open `http://localhost:3000` in your browser.

### 3. Typecheck & Production Build
```bash
npm run lint
npm run build
```

### 4. Run Production Build
```bash
NODE_ENV=production npm start
```

## Fault Tolerance & API Rate-Limit Resilience

- **Per-Source Isolation**: If any single external API (e.g., NASA POWER or Crossref) times out or rate-limits during testing, `/api/environment` and `/api/space-sources` continue returning data from the remaining healthy sources alongside explicit `sourceStatus` flags.
- **Last-Known-Good Cache Fallback**: Successful responses are retained in a fallback store in `server.ts` so transient upstream failures serve cached telemetry flagged `stale: true` rather than failing.
- **Offline Manual Digital Twin Fallback**: If all external weather endpoints are unreachable, the Bio-Dashboard provides an inline **Manual Environmental Input Fallback** (ambient temperature & humidity sliders) and a React `ErrorBoundary` so the application never renders a blank screen.
